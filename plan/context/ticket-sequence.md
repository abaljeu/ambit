# Ticket sequence

The standard sequence for a ticket folder.

1. build: [[plan/context/build-work2.md]]. The build records its outcome in the ticket file `<nn>-<name>-ticket.md`.
2. review: [[plan/context/review-work2.md]]. The review writes the review file `<nn>-review.md`.
3. refactor: [[plan/context/refactor-work2.md]], which writes `<nn>-refactor.md`
4. doc: [[plan/context/doc-work2.md]], which writes `<nn>-doc.md`

No step writes outcomes to `plan/*/reports/` or to separate check or stop files.

Follow the shared rules in [[plan/context/ticket-rules.md]].
