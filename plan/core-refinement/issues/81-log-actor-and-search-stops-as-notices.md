# 81 — Log Actor and search stops as Notices

**Status:** `defined`
**Type:** coding
**Blocked by:** [80 — Place Actor orders through PlaceOrder](80-place-actor-orders-through-placeorder.md)
**Trackers:** architecture

## Context

`RouteRegistration.searchDoor` calls `CoreMailboxApi.recordSearchStart` and `CoreMailboxApi.recordSearchStop`. `recordSearchStop` posts `CoreMsg.RecordSearchStop`, and `CoreMailboxLoad.runMsg` calls `CoreEventDispatch.actorStop`, which stores `EventBody.ActorStop` of the root id and `ActorSucceeded`. `CoreMailboxApi.cancelByFocus` posts `CoreMsg.CancelActor`, and `CoreMailboxActors.dispatchCancelActor` appends `EventBody.ActorStop` of the focus and `ActorCancelled` and finishes the pool entry; with no running Actor for the focus it appends nothing. A client `PostEvent` of `EventBody.Cancel` is handled in `dispatchPostEvent`. `CoreMailboxApi.actorStop` and `CoreDoor.actorStop` take only the `ActorResult`. `actorStop` posts `CoreMsg.ActorStop`, and `CoreMailboxActors.dispatchActorStop` finds the focus from the pool, appends `EventBody.ActorStop` of the focus and the result, and finishes the pool entry. `Order.Cancel` is in `src/Shared/MailboxLog.fs`, and after [80](80-place-actor-orders-through-placeorder.md) the `PlaceOrder` arm of `CoreMailboxLoad.dispatchMailbox` sends each order to its handler. `Notice` is in `src/Shared/History.fs`. `CoreMailboxLoad.applyNotice` handles each `Notice`, and `Database.writeNoticeRow` writes the graph node row a Notice changes. `appendEvent` writes each logged `Ev` to the `events` table. `ActorLive` reads the live focus set and the Actor result from `EventBody.ActorStart` and `EventBody.ActorStop`. `SyncLogic` sends a Notice body to `applyLoggedNotice`.

This ticket is decision 19 **One case each** in [Message shape](../cqrs-messages.md). `Notice.ActorStopped` of the focus id and the result is the one Actor stop: an Actor that is done posts it, and a Cancel posts it with `ActorCancelled`. The search stop is `Notice.SearchCancelled`. `CancelActor` and `ActorStop` leave `CoreMsg`.

### Acceptance Criteria

1. [ ] **Done** — `actorStop posts Notice.ActorStopped`. The log holds `EventBody.ActorStop` of the focus and the result, and the pool entry is finished. A focus with no running Actor gets `Error`, and the log gains no entry.
2. [ ] **Cancel** — `cancelByFocus posts Notice.ActorStopped`. The Actor for that focus finishes. The log holds `EventBody.ActorStop` of the focus and `ActorCancelled`, and the reply is `Ok`. `second Cancel for the same run logs one stop`: a second Cancel for that focus replies `Ok ()` and logs nothing.
3. [ ] **Search** — `recordSearchStop logs SearchCancelled`. The log holds the search start, then `Notice.SearchCancelled` of the root id.
4. [ ] **Search authority** — `recordSearchStop without authority returns Error`. The log gains no entry.
5. [ ] **Browser** — `ActorLive reads SearchCancelled`. `Notice.SearchCancelled` removes the root from the live set.
6. [ ] **Stored** — `SearchCancelled is stored in the events table`. Each `Notice.SearchCancelled` has an `events` row and reads back unchanged. No graph node row changes.
7. [ ] **Still working** — `upload, import, parse, Load, undo, and persist complete`.
