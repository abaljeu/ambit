## 1. Problem Statement

1. **GitHub is off Load and Save** — A person whose Workspace DataDir work tree is already a git work tree cannot send files to GitHub or bring files from GitHub through the same Load and Save Commands they already use. `src/Client/UpdateWorkspaceLoad.fs` `loadOp`. `src/Client/UpdateSave.fs` `saveOp`. `src/Server/WorkspaceGit.fs` `isRepo`. `src/Server/DocumentPersistWrite.fs` `ensureWorkspaceRepo`.
2. **Desk path is Ambit↔Ambit only** — WebDAV Upload and Download move files between the App and Server. They do not talk to the GitHub remote. [[doc/current/workspace-file-sync.md]]. `src/Shared/dotnet/WorkspaceFileSync.fs` `post` and `getStaged`. `src/Server/WorkspaceWebDav.fs` `registerRoutes`.
3. **No Server-git when a remote exists** — When that work tree has a remote, the person has no Server Actor that pulls and pushes the tracked branch on that remote. `src/Server/WorkspaceGit.fs` `remoteExists` and `trackedBranch`. `src/Server/GithubTransportActor.fs` `start`.
4. **Config and credentials already live in git** — The operator already sets `git remote` and host credentials so git works. The person does not want a second Server branch map or GitHub secrets stored in Ambit. `src/Server/WorkspaceGit.fs` `trackedBranch`. `src/Shared/dotnet/GitRun.fs` `gitExec`.

## 2. Solution

1. **Server Actor** — A Server Actor pulls and pushes for round-trip v1. Actor is the glossary word. That Actor is the Server Actor and is not a new Kind. The App stays thin. The App is not the git Actor host. The same Actor shape serves every device that maps through Server. `src/Server/GithubTransportActor.fs` `GithubTransportActor.start`. `src/Client/LoadSaveCommandClient.fs` `run`.
2. **Workspace is the git home** — Every Workspace’s DataDir work tree is a git work tree. Any Workspace connects, with no allowlist and no special label. Server-git applies when a remote exists. Else desk. `src/Server/DocumentPersistWrite.fs` `ensureWorkspaceRepo`. `src/Server/WorkspaceGit.fs` `ensureInit` and `remoteExists`. `src/Shared/PathPick.fs` `PathPick.choose`.
3. **Config is git on that work tree** — Config is `git remote` plus the current branch and its upstream. There is no separate Server branch map in v1. Pull and push use the same tracked branch. `src/Server/WorkspaceGit.fs` `currentBranch` and `trackedBranch`. `src/Server/WorkspaceGit.fs` `WorkspaceTrackedBranch`.
4. **Fast-forward push, remote-wins pull** — git push stays fast-forward-only, a conflict names at least one file path, other failures use a short error condensed from git, and git Load commits one remote-wins merge of the tracked branch as part of the pull, including a content conflict and an edit-versus-delete. `src/Server/WorkspaceGit.fs` `ensurePushConfig`, `pullTrackedBranch`, `completeRemoteWins`, `resolveUnmergedPath`, `condenseGitError`, `commitTracked`, and `pushTrackedBranch`. `src/Server/GithubTransportActor.fs` `pullTracked`. The later parse step that merges the pulled file with the Server graph stays on [[plan/core-refinement/project.md]].
5. **Load and Save** — Load and Save are the person-facing Commands. Load sends one core message, `LoadSaveCommandRequest`, and that message is not a Command and not an Event. A Node exists and has data. Load's subject is a Workspace Node, a Directory Node, or a File Node. A selected node inside a File Node uses that owning File Node, and several selected nodes in one File Node yield one message. Explicit pre-picks are git Load, git Save, desk Load, and desk Save. Plain Save, and plain Load of a Workspace Node, are git when a remote exists, else desk. A plain Load of a File or a Directory is the Load actor in 23 — Run the Load actor for Git and Neither. Load or Save starts the Server Actor. The Actor uses Focus to name the Workspace work tree. Save uses the same door as Load. `src/Shared/History.fs` `LoadSaveCommandRequest`. `src/Shared/CommandEntry.fs` `CommandId`. `src/Client/Commands.fs` `commandRegistry`. `src/Client/UpdateHelpers.fs` `loadSaveCommandRequest`. `src/Client/LoadSaveCommandClient.fs` `run`. `src/Shared/PathPick.fs` `LoadSubject` and `PathPick.resolveCommand`. `src/Shared/WorkspaceUpload.fs` `loadSubjects`. `src/Server/LoadSaveRouting.fs` `resolvePath`. `src/Server/Api.fs` `postLoadSaveCommand`. `src/Server/RouteRegistration.fs` `githubOperation`. `src/Server/GithubTransportActor.fs` `start` and `workspaceFromFocus`. `src/Server/Core/CoreMailboxApi.fs` `startLoadSaveCommand` and `coreMailboxStartActorFromFunction`. `src/Server/Core/DeskLoadPush.fs` `runLoadSave`. `src/Server/Core/CoreMailboxFilesAxis.fs` `markUnparsedThenPush`. `src/Shared/GraphQuery.fs` `enclosingWorkspace`. `src/Server/DocumentPersistPath.fs` `workspaceRootFor`.
6. **Person-started only** — Pull and push start when the person runs Load or Save, or an explicit git or desk pre-pick. A schedule, a post-Persist hook, and a post-Download hook stay outside v1. When a remote exists, plain Save and plain Load of a Workspace prefer git first. A plain Load of a File or a Directory is that same Load actor. Daily save commits DataDir repos and does not pull or push. `src/Server/GithubTransportActor.fs` `pullTracked` and `pushAfterPull`. `src/Server/LoadSaveRouting.fs` `resolvePath`. `src/Shared/PathPick.fs` `PathPick.resolveCommand`. `src/Server/DailyGitSave.fs` `tryRun`.
7. **Thin handoff to Core** — After files land, this Project locks the workspace, receives the files, and informs the revised Core of changes. Core works through the changes ([[plan/core-refinement/project.md]]). The WebDAV Upload and Download path remains. When a remote exists, plain Save and plain Load of a Workspace still prefer git first. A plain Load of a File or a Directory is that same Load actor. Parse thread home stays [[plan/parse-thread/project.md]]. `src/Server/GithubTransportActor.fs` `finishLoadPull`. `src/Server/LazyLoadReconciliationServer.fs` `reconcileFromChanges`. `src/Shared/History.fs` `ActorChanges`. [[doc/current/workspace-file-sync.md]].
8. **Host git credentials** — Ambit does not store GitHub credentials in appsettings, user-secrets, Graph, or DataDir. The Actor invokes `git`. git loads credentials from the host credential helper. On Server that is the host’s git. `src/Shared/dotnet/GitRun.fs` `gitExec`. `src/Server/GithubTransportActor.fs` `workspaceGit`.
9. **Skip list is `.gitignore`** — Skip on the GitHub remote is whatever `.gitignore` already says. The person edits that file. Ambit has no skip config key. When `.amb` or other notes are listed there, they are skipped on the remote. When excluded, offsite backup of those notes is Ambit Server DataDir through WebDAV Upload and Download plus Server git daily save, not the mapped repo remote. Git commit honors that file in `src/Server/GitSave.fs` `commitAll`. WebDAV omission reads it in `src/Server/WorkspaceWebDav.fs` `isOmitted` and `src/Shared/dotnet/GitCheckIgnore.fs` `isEffectivelyIgnored`. Daily save commits in `src/Server/DailyGitSave.fs` `tryRun`. WebDAV transit is [[doc/current/workspace-file-sync.md]].
10. **Git Load/Save are Workspace-scoped** — When git Load or git Save runs, including explicit git Load from a subnode, pull and push operate on the whole Workspace work tree and its tracked branch. A plain Load of a File or a Directory starts that Load actor for the Git arm and for the Neither case. After files land, inform Core ([[plan/core-refinement/project.md]]). `src/Server/GithubTransportActor.fs` `runLoadBody` and `runSaveBody`. `src/Server/WorkspaceGit.fs` `pullTrackedBranch` and `pushTrackedBranch`. `src/Shared/PathPick.fs` `PathPick.effectiveLoadPath`.
11. **git Save sequence** — Save persists the focus if it is not an ordinary node, then commits, pulls, and pushes.

    - That persist marks the focus Parsed and pushes it on the persistence stack, including when that node is already Persisted. When that persist cannot mark the focus Parsed, Save fails. Save keeps that focus. `src/Server/GithubTransportActor.fs` `persistFocusWhenNotOrdinary` and `persistFocus`.
    - commit `src/Server/GithubTransportActor.fs` `commitAndPull`. `src/Server/WorkspaceGit.fs` `commitTracked`.
    - pull `src/Server/GithubTransportActor.fs` `pullAndReadHeads`. `src/Server/WorkspaceGit.fs` `pullTrackedBranch`.
    - push `src/Server/WorkspaceGit.fs` `pushTrackedBranch`. `src/Server/GithubTransportActor.fs` `pushAfterPull`.

    Pull uses the same resolution as Solution 4 — Fast-forward push, remote-wins pull. That pull then reconciles received files and loads that Workspace, the same steps as git Load. A conflict is merged automatically. A conflict alone leaves the pull successful. `src/Server/WorkspaceGit.fs` `completeRemoteWins`. `src/Server/GithubTransportActor.fs` `applyPulledChanges`. `src/Server/LazyLoadReconciliationServer.fs` `reconcileFromChanges`. `src/Server/Core/CoreDoor.fs` `loadNode`.

## 3. User Stories

1. **Workspace is a git work tree** — As a person, I want every Workspace’s DataDir work tree to be a git work tree, so that GitHub transport has a git home without a special label. `src/Server/DocumentPersistWrite.fs` `ensureWorkspaceRepo`. `src/Server/WorkspaceGit.fs` `ensureInit`.
2. **Every Workspace may connect** — As a person, I want any Workspace to use Server-git when a remote exists, so that there is no allowlist. `src/Shared/PathPick.fs` `PathPick.choose`. `src/Server/WorkspaceGit.fs` `remoteExists`.
3. **Server-git when a remote exists** — As a person, I want the Server-git path when a remote exists and the desk path when it does not, so that one check chooses the path. A plain Load of a File or a Directory is the Git arm or the Neither case in 23 — Run the Load actor for Git and Neither. `src/Server/LoadSaveRouting.fs` `resolvePath`. `src/Shared/PathPick.fs` `PathPick.resolveCommand`.
4. **Config in git** — As an operator, I want config to live in git on that work tree (`git remote` plus current branch and upstream), so that Ambit does not keep a Server branch map in v1. `src/Server/WorkspaceGit.fs` `trackedBranch`.
5. **Same tracked branch** — As a person, I want pull and push to use the same tracked branch of the whole Workspace work tree, so that round-trip v1 does not switch branches or go file-level. `src/Server/WorkspaceGit.fs` `WorkspaceTrackedBranch`, `pullTrackedBranch`, and `pushTrackedBranch`.
6. **Fast-forward only** — As a person, I want a conflicted or non-fast-forward push rejected with an error that names at least one file path, so that I see what git refused. Pull is Solution item 4 — Fast-forward push, remote-wins pull. `src/Server/WorkspaceGit.fs` `ensurePushConfig`, `pushTrackedBranch`, and `condenseGitError`.
7. **Remotes accept push** — As an operator, I want remotes that accept push (not PR-only), so that the Server Actor can push the tracked branch. `src/Server/WorkspaceGit.fs` `pushTrackedBranch`.
8. **Load** — As a person, I want the Load command to send a core message through the mailbox, so that the Server Actor runs when PathPick chooses git. A desk Load's subject is a Workspace Node, a Directory Node, or a File Node. The parse push marks that subject Unparsed, then pushes it onto the parse stack. The mailbox posts Events. The Load command does not send a Command or an Event. `src/Client/UpdateWorkspaceLoad.fs` `loadOp`. `src/Server/Api.fs` `postLoadSaveCommand`. `src/Server/GithubTransportActor.fs` `loadActorFunction`. `src/Server/Core/CoreMailboxLoad.fs` `dispatchLoad`. `src/Server/Core/CoreMailboxFilesAxis.fs` `markUnparsedThenPush`.
9. **Save** — As a person, I want Command Save to use the same mailbox and actor-pool wiring as Load, so that the Server Actor runs when PathPick chooses git. `src/Client/UpdateSave.fs` `saveOp`. `src/Server/RouteRegistration.fs` `githubOperation`. `src/Server/GithubTransportActor.fs` `saveActorFunction`.
10. **git Load** — As a person, I want an explicit git Load pre-pick, so that I merge the tracked remote branch of the whole Workspace work tree, even from a subnode, and commit that merge as part of the pull, then inform Core that files changed. That merge is Solution item 4 — Fast-forward push, remote-wins pull. `src/Client/Commands.fs` `prePickCmd`. `src/Client/UpdateWorkspaceLoad.fs` `loadOpFor`. `src/Server/WorkspaceGit.fs` `pullTrackedBranch` and `completeRemoteWins`. `src/Server/GithubTransportActor.fs` `runLoad`.
11. **git Save** — This story is retired. The sequence is Solution 11 — git Save sequence.
12. **desk Load** — As a person, I want an explicit desk Load pre-pick, so that the Load command sends a core message whose subject is that Workspace Node, Directory Node, or File Node. The parse push marks that subject Unparsed, then pushes it onto the parse stack. The mailbox posts Events. Desktop-mapped WebDAV waits for the design above. The recorded transit is [[doc/current/workspace-file-sync.md]]. `src/Client/UpdateWorkspaceLoad.fs` `loadOpFor` and `deskLoadOp`. `src/Server/Core/DeskLoadPush.fs` `runLoadSave`. `src/Server/Core/CoreMailboxFilesAxis.fs` `markUnparsedThenPush`. `src/Shared/dotnet/WorkspaceFileSync.fs` `post`.
13. **desk Save** — As a person, I want an explicit desk Save pre-pick, so that I take the desk file path when I choose desk. `src/Client/UpdateSave.fs` `saveOpFor` and `deskSaveOp`. `src/Server/Api.fs` `gitSave`. `src/Server/GitSave.fs` `commitAll`.
14. **Plain Load prefers git** — As a person, I want plain Load of a Workspace Node to start the git actor when a remote exists and to use desk Load otherwise, so that I do not pick a path when the default is enough. A plain Load of a File or a Directory uses that Load actor even when a remote exists. A selected node inside a File Node uses that owning File Node, and several selected nodes in one File Node yield one message. Explicit git Load still pulls the Workspace. `src/Shared/PathPick.fs` `PathPick.resolveCommand` and `PathPick.plainLoadPath`. `src/Shared/WorkspaceUpload.fs` `loadSubjects`. `src/Server/GithubTransportActor.fs` `runLoadBody`.
15. **Plain Save prefers git** — As a person, I want plain Save to be git Save when a remote exists and desk Save otherwise, so that I do not pick a path when the default is enough. `src/Shared/PathPick.fs` `PathPick.choose`. `src/Client/UpdateSave.fs` `saveOp`.
16. **No automatic pull or push** — As a person, I want pull and push only when I run Load or Save, or an explicit git or desk pre-pick, so that no schedule, post-Persist, or post-Download git starts a round-trip. Daily save commits and does not pull or push. `src/Server/GithubTransportActor.fs` `start`. `src/Server/DailyGitSave.fs` `tryRun`.
17. **Inform Core after files land** — As a person, I want git Load to inform Core after the pull lands, so Core can work through the changes ([[plan/core-refinement/project.md]]). A web desk Load sends a core message whose subject is that Workspace Node, Directory Node, or File Node. The parse push marks that subject Unparsed, then pushes it. The mailbox posts Events. Desktop-mapped WebDAV waits for the design above. The recorded transit is [[doc/current/workspace-file-sync.md]]. `src/Server/GithubTransportActor.fs` `finishLoadPull`. `src/Server/Core/CoreMailboxLoad.fs` `dispatchLoad`. `src/Shared/dotnet/WorkspaceFileSync.fs` `post`.
18. **WebDAV remains** — As a person, I want WebDAV Upload and Download to remain, so that Ambit to Ambit file transit stays available beside Server-git. [[doc/current/workspace-file-sync.md]]. `src/Server/WorkspaceWebDav.fs` `registerRoutes`. `src/Client/UpdateWorkspaceDownload.fs` `downloadOp`.
19. **Server Actor does the round-trip** — As a person, I want a Server Actor, started from Load or Save, to pull and push using Focus as the Workspace work tree, so that the App stays thin and is not the git Actor host. `src/Server/GithubTransportActor.fs` `start` and `workspaceFromFocus`. `src/Client/LoadSaveCommandClient.fs` `run`.
20. **One Actor shape through Server** — As a person, I want the same Actor shape on every device that maps through Server, so that this is not a per-App clone protocol. `src/Server/GithubTransportActor.fs` `GithubTransportActor`. `src/Server/Api.fs` `postLoadSaveCommand`.
21. **Host git credentials** — As an operator, I want the Actor to invoke `git` and git to load host credentials, so that Ambit does not store GitHub credentials in appsettings, user-secrets, Graph, or DataDir. `src/Shared/dotnet/GitRun.fs` `gitExec`.
22. **Skip list is `.gitignore`** — As a person, I want the GitHub remote to skip whatever `.gitignore` already says, so that I edit that file and Ambit does not invent a skip key. `src/Server/GitSave.fs` `commitAll`.
23. **Backup when `.amb` is excluded** — As a person, I want excluded `.amb` notes to stay on Server DataDir through WebDAV Upload and Download and Server git daily save, so that exclude-from-repo is not desk-local-only. `src/Server/DailyGitSave.fs` `tryRun`. `src/Server/DocumentPersistWrite.fs` `writeDocument`. [[doc/current/workspace-file-sync.md]]. `src/Shared/dotnet/GitCheckIgnore.fs` `isEffectivelyIgnored`.
24. **Workspace-scoped git** — As a person, I want git Load and git Save to always pull or push the whole Workspace work tree and tracked branch, so that invoking Load or Save from a subnode never becomes file-level git. `src/Server/GithubTransportActor.fs` `runLoadBody` and `runSaveBody`.
25. **Actor start door** — As a person, I want Load or Save to start the Server Actor through the mailbox and the actor pool, so that Focus names the work tree and Save uses the same door as Load. `src/Server/Core/CoreMailboxApi.fs` `coreMailboxStartActorFromFunction`. `src/Server/GithubTransportActor.fs` `start`. `src/Client/Commands.fs` `commandRegistry`.
26. **Reject UX** — As a person, I want a conflict reject to name at least one file path and other failures to show a matching short git-condensed error, so that Load and Save rejects reflect what git reported. That wording covers network, credentials, a missing remote, and a non-fast-forward push. `src/Server/WorkspaceGit.fs` `pullTrackedBranch`, `commitTracked`, `condenseGitError`, and `remoteExists`.
27. **Persist stays independent of git Save** — This story is retired. The sequence is Solution 11 — git Save sequence.
