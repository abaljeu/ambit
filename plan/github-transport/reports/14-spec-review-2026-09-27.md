# 14 — Route Load and Save by path pre-pick — Spec review

## Findings

1. **Command-request door is only partial.** Requirement: “1.2.5 Use the command-request door — Load and Save send a load/save command request through the mailbox to the actor pool, not through Run or `?git`.” `Api.postLoadSaveCommand` handles and resolves the load/save request in the HTTP API. The mailbox sees separate `getState` and, only for Git, `StartPeerActor` messages; it never receives a load/save command request. Desk requests never reach the actor pool at all. This does not implement the specified command-request → mailbox → actor-pool door.

2. **Git Load does not preserve Load completion.** Requirement: “1.2.6 Preserve Load completion — Each Load form keeps today's Parse / graph-push coupling after files land; this ticket does not expand selection-scoped Parse.” The Peer Actor does run whole-Workspace `reconcileWorkspace`, but `startPeerActor` returns before that work completes. The HTTP response therefore contains the ActorStart tail, and `LoadSaveCommandClient` dispatches ordinary `CommandDone`; `applyCommandEvents` emits no `tryStartLoadFetch` effect. Unlike desk Load, git Load never schedules the selected-target Fetch+Poll completion hop after Parse/graph-push, so newly resident or unloaded selected content is not fetched as required.
