# Expression result insert today

A leading `=` expression does not place Nodes for Find or for Move. [findRootOp](src/Client/UpdateOps.fs) and [moveNodesOp](src/Client/UpdateOps.fs) open the search dialog, and that dialog does not evaluate the expression. Run places Answers as Children under the focused Node. [ExprRun.run](src/Shared/ExprRun.fs) builds that plan.

## 1. Find — Where a leading `=` expression places Nodes for Find

1. **Command path.** The Find command opens the search dialog. [findRootOp](src/Client/UpdateOps.fs) calls [openSearchDialogWithOnPick](src/Client/SearchDialog.fs) with the name Find and with [searchPickSetRoot](src/Shared/ViewModelSearch.fs).
2. **Expression path.** The expression path is absent on Find. [startCache](src/Client/SearchDialog.fs) loads hits with [startSearch](src/Shared/ViewModelSearch.fs). startSearch does not call [tryHits](src/Shared/ExprDialog.fs).
3. **Query parts.** A leading `=` stays in the query text. [parseSearchParts](src/Shared/ViewModelSearch.fs) splits the trimmed query on space, tab, line feed, and carriage return. [nodeMatchesAllParts](src/Shared/ViewModelSearch.fs) keeps a Node only when every part matches. [nodeMatchesPart](src/Shared/ViewModelSearch.fs) matches the Node text or the Node name.
4. **Path part.** A part that [RefExpr.parse](src/Shared/RefExprParse.fs) accepts also matches those Node ids. [buildPartFilter](src/Shared/ViewModelSearch.fs) stores that id set. A parse error stores an empty id set. The character `=` is not a name character. [isNameChar](src/Shared/RefExprParse.fs) omits it, so [tokenize](src/Shared/RefExprParse.fs) rejects a part that starts with `=`.
5. **Hit order.** startSearch queues the zoom Node first and the graph root after that zoom walk. [nextDiscoveryNode](src/Shared/ViewModelSearch.fs) visits each Node once and queues its Children. The dialog shows that list. It does not change the Graph.
6. **Library list.** [searchNodes](src/Shared/ViewModelSearch.fs) calls tryHits when the trimmed query starts with `=`. That branch returns the tryHits list and does not call startSearch. [trySearchResultAtDisplayIndex](src/Shared/ViewModelSearch.fs) calls searchNodes. The Find dialog does not call searchNodes.
7. **tryHits input.** tryHits uses the zoom-root Node as the input Answer. It wraps `graph.nodes.[zoomRoot]` as [ExprAnswer.Node](src/Shared/ExprAnswer.fs). [evalOutcome](src/Shared/ExprCompile.fs) compiles the source after the `=` and calls [ExprEval.toList](src/Shared/ExprEval.fs). [ExprEval](src/Shared/ExprEval.fs) yields Answers. It does not write Children.
8. **tryHits list.** A parse failure, a type failure, a Text result, or an empty result becomes an empty list. [tryHits](src/Shared/ExprDialog.fs) does that. A Node result keeps each Node Answer as a search row with the Node id, text, and name. tryHits drops any other Answer in that result. tryHits does not insert Nodes.
9. **Pick.** A picked hit does not add Children. searchPickSetRoot sets the zoom root and builds a new site map with [buildSiteMapFrom](src/Shared/ViewModelSiteMap.fs). When the hit has Children, the zoom root becomes the hit and the selection is the first Child. [firstChildSelection](src/Shared/ViewModelSiteMap.fs) builds that selection. When the hit has no Children, the zoom root becomes the structural parent from [tryFindParentAndIndex](src/Shared/GraphQuery.fs) and the selection is the hit. [childSelectionAt](src/Shared/ViewModelSiteMap.fs) builds that selection. When that parent is absent, the zoom root stays the hit and the selection is the first Child, or none when the hit has no Children. The function returns no effects.

## 2. Move — Where a leading `=` expression places Nodes for Move

1. **Command path.** Move Selected opens the same search dialog as Find. [moveNodesOp](src/Client/UpdateOps.fs) calls [openSearchDialogWithOnPick](src/Client/SearchDialog.fs) with [searchPickMoveAfterHit](src/Client/UpdateOps.fs). The expression path is absent. The dialog uses [startSearch](src/Shared/ViewModelSearch.fs).
2. **No selection.** When no Nodes are selected, moveNodesOp returns the same model. It does not open the dialog.
3. **Insert parent.** A picked hit is the new parent. [makeNodeRangeForInsertingUnder](src/Shared/GraphQuery.fs) sets the insert index to the Child count of that Node. The range start and the range end are that index. When the hit id is not in the Graph, the function returns none and the model stays the same.
4. **Moved Nodes.** [moveNodeFromTo](src/Client/UpdateMove.fs) moves the selected Children to that index. [replaceOpsForMove](src/Client/UpdateMove.fs) removes them from the old parent and inserts them under the hit when the parent changes. The moved Nodes are the selection. They are not expression Answers. searchPickMoveAfterHit sets stay-at-source to true, so the selection stays at the old place. [selectionAfterStructuralMove](src/Shared/ViewModelSelection.fs) does that.
5. **tryHits.** tryHits does not move Nodes. [tryHits](src/Shared/ExprDialog.fs) returns a Node list or an empty list. The Move command does not call tryHits.

## 3. Run — Where a leading `=` expression places Nodes for Run

1. **Command.** The Run command id is Exec. [execRunOp](src/Client/Commands.fs) is the handler. The command list binds Exec to execRunOp. The display name is Run. [CommandEntry](src/Shared/CommandEntry.fs) stores that name.
2. **Focused line.** Run reads the focused Node text. [focusedNodeId](src/Shared/ViewModelSelection.fs) is that Node. Run does not evaluate an ancestor line. [runPlanOnNode](src/Shared/AmbleRun.fs) passes `graph.nodes.[focusNodeId].text` to [runPlan](src/Shared/AmbleRun.fs).
3. **Scan stop.** [isAmbleScanStop](src/Shared/CommandRequest.fs) is true when the first `=` or `?` on the owner path from the focus to the zoom is not a `?` command. [isScanStopText](src/Shared/CommandRequest.fs) treats any `=` in the text as a stop. A focused leading `=` is that stop. [tryStart](src/Shared/CommandRequest.fs) returns an error when that path has no `?` command. A `=` line is not an Actor start.
4. **Local call.** When the scan stop is an Amble line, execRunOp calls [execAmbleRunOp](src/Client/Commands.fs). When tryStart fails and [shouldExec](src/Shared/AmbleRun.fs) is true, execRunOp also calls execAmbleRunOp.
5. **Run statement.** [classify](src/Shared/ExprRun.fs) trims the line. A line that starts with `=` has no name and has the source after `=`. [isRunStatement](src/Shared/ExprRun.fs) is true for that line. shouldExec is true for a normal Node with that line. [isSpecialFocus](src/Shared/AmbleRun.fs) makes shouldExec false for a special Node, so Run does not change that Node.
6. **Delete first.** When the focus has Children, execAmbleRunOp calls [deleteChildSpan](src/Client/UpdateOps.fs) for the full Child span. When Children remain, Run stops. It does not call ExprRun.
7. **Plan entry.** [runAmbleOp](src/Client/UpdateAmbleRun.fs) calls runPlanOnNode. For a normal Node, runPlan calls [ExprRun.run](src/Shared/ExprRun.fs). The input Answer is the focus Node. [planExpr](src/Shared/ExprRun.fs) wraps `graph.nodes.[focusId]` as [ExprAnswer.Node](src/Shared/ExprAnswer.fs).
8. **Empty source.** A leading `=` with an empty source applies [noMatches](src/Shared/ExprRun.fs). noMatches calls [blueletterChild](src/Shared/ExprRun.fs). That plan adds one new Node with the text "No matches found" and the class blueletter. The Child is an owner Child under the focus. [replaceChildren](src/Shared/ExprRun.fs) writes that Child list with [Op.Replace](src/Shared/History.fs).
9. **Errors.** An infer error or a compile error also calls blueletterChild. The Child text is the error text. [inferType](src/Shared/ExprCompile.fs) and [compile](src/Shared/ExprCompile.fs) supply that error.
10. **Answer page.** A successful compile calls [planFromPred](src/Shared/ExprRun.fs). [ExprEval.take](src/Shared/ExprEval.fs) keeps at most [maxMaterialisedAnswers](src/Shared/ExprRun.fs). That limit is 50. An empty page calls noMatches. A non-empty page calls [materialise](src/Shared/ExprRun.fs). ExprEval does not write Children.
11. **Child kind.** [addAnswer](src/Shared/ExprRun.fs) turns a Node Answer that is in the Graph into a reference Child. [ChildNode.reference](src/Shared/Model.fs) builds that Child. The Node stays in the Graph. addAnswer turns a Text Answer into a new Node and an owner Child. [Op.NewNode](src/Shared/History.fs) creates the Node. [ChildNode.owner](src/Shared/Model.fs) builds the Child. addAnswer skips a Node Answer that is not in the Graph.
12. **Child order.** materialise adds each kept Answer at the front of the lists and then reverses the lists. The Child order matches the Answer order. replaceChildren replaces the focus Children with that list.
13. **Apply.** [applyRunPlan](src/Client/UpdateAmbleRun.fs) applies the ops with [applyAndPost](src/Client/UpdateHelpers.fs). These plans set unfold to true. When [focusedInstanceId](src/Shared/ViewModelSelection.fs) returns an id, [applyUnfold](src/Shared/AmbleRun.fs) expands that instance one level. [expandEntry](src/Shared/ViewModelSiteMap.fs) inserts the Child rows in the site map. When that id is absent, applyRunPlan leaves the site map from applyAndPost.

## 4. Insert under the line — Whether any path inserts Answers as Children under the expression line

1. **Run insert.** Run is the path that inserts Answers as Children under the expression line. The expression line is the focused Node. [addAnswer](src/Shared/ExprRun.fs), [materialise](src/Shared/ExprRun.fs), and [replaceChildren](src/Shared/ExprRun.fs) do that insert. A Node Answer becomes a reference Child. A Text Answer becomes a new owner Child.
2. **Find.** Find does not insert Answers as Children. [searchPickSetRoot](src/Shared/ViewModelSearch.fs) changes the zoom root and the selection.
3. **Move.** Move does not insert expression Answers. [searchPickMoveAfterHit](src/Client/UpdateOps.fs) moves the selected Nodes under the picked hit.
4. **List functions.** [tryHits](src/Shared/ExprDialog.fs) and [searchNodes](src/Shared/ViewModelSearch.fs) do not insert Children. They return a list. [ExprEval](src/Shared/ExprEval.fs) does not insert Children.
5. **Status Child.** The blueletter Child for an error or for no matches is a new owner Child under the focus. [blueletterChild](src/Shared/ExprRun.fs) builds it. That Child is not an Answer from the stream.
