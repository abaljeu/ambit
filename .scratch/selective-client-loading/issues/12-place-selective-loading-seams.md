# Place selective-loading module seams

Type: grilling
Status: resolved
Blocked by: 11

## Question

Which Shared, Client, and Server modules should own residency data, the pure server load-state mode expansion, client command request selection, snapshot installation, command-specific continuations, and synchronization integration, and what minimal interfaces, discovery-occurrence descriptors, and result types would make those responsibilities testable and implementation-ready without introducing a client-wide loading planner?

## Answer

- [[src/Shared/Model.fs]] owns the residency unions required by `Node`: child lists distinguish `Unknown` from `Loaded of ChildNode list`, and owners distinguish `Unknown` from `Known of NodeId`. [[src/Shared/GraphBuild.fs]] remains the one derived-index builder, using only `Loaded` lists for occurrences and only `Known` owners for owner indexes.
- Add a focused Shared `LoadSnapshot` module in [[src/Shared/LoadSnapshot.fs]]. It owns the closed `LoadMode = Direct | ArtifactClosure | Workspace`, target normalization, snapshot fact types, and the pure authoritative expansion interface `expand : Graph -> LoadMode -> NodeId list -> Result<SnapshotFacts, string>`. It contains no trigger policy, I/O, client state, or future-mode abstraction.
- [[src/Shared/ApiResponses.fs]] owns `LoadSnapshotRequest`, header and loaded-list wire facts, and one flat `GraphSyncTransaction` containing `baseRevision: Revision option`, resulting `revision`, ordered history actions, deduplicated `headers`, `tombstones`, and authoritative `loadedLists`. Poll wraps the same transaction with its build/readiness metadata and supplies no loaded lists; bootstrap uses `baseRevision = None`; later load responses include requested loaded lists. Existing serialization modules own the codecs.
- [[src/Shared/SyncLogic.fs]] owns construction and atomic application of `GraphSyncTransaction`. Application replays the history actions against projected State, installs supplemental and requested facts, rebuilds indexes, and advances revision in one `Result<State, string>` operation. The client coordinator classifies stale base-revision or mutation-epoch responses before application; an application error is therefore a protocol or coding invariant failure requiring full bootstrap.
- Add a pure Shared `LoadCoordinator` module in [[src/Shared/LoadCoordinator.fs]], compiled into the existing `Shared.Tests` test surface. A normalized `LoadKey` is `(LoadMode, sorted distinct target IDs)`. Separate `LoadInfo` state in `VM` maps each key to `Waiting` or `InFlight` state plus command-owned `Updater` continuations; identical requests coalesce by appending continuations, while non-identical requests remain separate.
- `LoadCoordinator` exposes request, waiting-dispatch, and completion transitions returning the existing `VM * Effect list` shape. It owns dispatch eligibility, captured base revision and mutation epoch, stale-response discard and still-required retry, progress, failure cleanup, transaction installation, and continuation folding. It never chooses a mode or target. Transport failure abandons the affected continuations with normal feedback; invariant failure requests bootstrap.
- `SyncInfo` gains only the client mutation epoch shared by poll and load compare-and-swap guards. Concurrent load lifecycle state does not enter the single-valued `SyncState` or [[src/Shared/SyncPlanner.fs]].
- Command-specific continuations remain `Updater` closures owned by their invoking commands. They capture minimal stable intent and revalidate it against the post-install `VM`; a stale or missing navigation, search, or move intent returns unchanged state. A central continuation-token union or interpreter is rejected because it would make the coordinator understand command policy.
- `NodeSearchResult` gains `discoveryIngress`, reusing the existing parent-nearest-first `(parentId, childIndex) list` shape of `VM.zoomIngress`. [[src/Shared/ViewModelSearch.fs]] carries that path through resident-only breadth-first discovery, and [[src/Shared/ViewModelOccurrence.fs]] owns path validation, shifted-index repair by child identity, and framing through the preserved first occurrence.
- Existing Client command modules choose fixed modes and targets directly: [[src/Client/UpdateOps.fs]] owns navigation, Find-commit, and Move-commit requests; [[src/Client/UpdateWorkspaceSync.fs]] owns the final explicit Load request. [[src/Client/View.fs]] only renders residency/progress and dispatches commands. No client-wide loading planner is introduced.
- [[src/Client/App.fs]] remains the effect interpreter for post-bootstrap load HTTP and dispatches typed completion messages. It performs no graph semantics. The first no-revision request remains a thin special path in [[src/Client/Program.fs]] and `App`: [[src/Client/SessionState.fs]] supplies remembered zoom, owning Workspace, and fold preferences; bootstrap shares the codec and atomic installer but does not create ordinary `LoadInfo` state. The old `/state` route may remain, but normal client startup no longer depends on it.
- `AgentHandle` gains one typed atomic capture operation taking an optional base revision and returning the fully resident graph, current revision, and the exact change-request tail through that revision. `FileAgent` and `DbAgent` each satisfy it with one mailbox message; they do not know load modes or build endpoint responses.
- [[src/Server/Api.fs]] owns request decoding and response assembly. Poll and the new load-snapshot endpoint call the same atomic `AgentHandle` capture, use Shared `SyncLogic` to build catch-up facts, optionally use Shared `LoadSnapshot.expand`, and encode the resulting transaction. [[src/Server/RouteRegistration.fs]] owns only route registration.
- `Shared.Tests` covers residency/index invariants, all mode expansions, projected Change/Undo/Redo replay, transaction application and failure atomicity, coordinator coalescing/stale/retry/continuation behavior, and discovery-occurrence framing. `Server.Tests` covers atomic backend capture and endpoint assembly. No Client-specific test harness is required.
