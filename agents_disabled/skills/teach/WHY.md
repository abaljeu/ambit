# Why — teach

Recipe: [[SKILL.md]]. Formats: [[MISSION-FORMAT.md]], [[RESOURCES-FORMAT.md]], [[LEARNING-RECORD-FORMAT.md]], [[GLOSSARY-FORMAT.md]].

Deep learning needs three strands:

- **Knowledge** — from high-quality, high-trust resources
- **Skills** — through interactive lessons grounded in that knowledge
- **Wisdom** — from real interaction with other learners and practitioners

Some topics lean knowledge (theoretical physics); some lean skills (yoga). Wisdom questions default to answering, then pointing at a high-reputation **community** unless the user opts out.

## Fluency vs storage

- **Fluency strength** — in-the-moment retrieval
- **Storage strength** — long-term retention (the real goal)

Fluency can feel like mastery. Design lessons for storage via desirable difficulty: retrieval practice, spacing, and interleaving (skills practice only).

## Knowledge vs skills in a lesson

Teach only the knowledge required for the skill, then practice through a tight feedback loop. For knowledge, difficulty eats working memory — keep it light. For skills, effortful retrieval builds storage; quizzes and real-world steps both work when feedback is immediate. Quiz options match in word (and character) count so formatting does not leak the answer.

## Lessons and reference

A lesson is beautiful (Tufte-leaning), short, and tied to the mission. Lessons are rarely revisited; reference documents are — keep them the compressed essence. Glossaries, once created, bind every lesson's language.
